# Business Requirement Document (BRD) — الإصدار v4

**المشروع:** نظام إدارة ورش النجارة "ورشتي" — ERP متكامل
**الجهة:** ورش نجارة سيلا والفيوم — م. مصطفى
**تاريخ الإصدار:** 10 يونيو 2026
**نظام التشغيل:** تطبيق ويب (Mobile-First) — Offline — ملف HTML واحد

---

## 1. نظام تسجيل الدخول
- دخول بكلمة سر رئيسية (Master Password) — SHA-256 hash
- 5 محاولات فاشلة → تأخير 30 ثانية
- Remember token للبقاء مسجلاً
- تعيين كلمة سر في أول استخدام (setup flow)
- المستخدم هو المالك فقط

---

## 2. نظرة عامة على النظام

نظام ERP متكامل لإدارة ورشتي نجارة (سيلا والفيوم)، يجمع بين:
- **دفتر الديون (Debt Register):** حسابات الأشخاص — كل شخص ليه حساب مستقل بأخذت/عطيت
- **دفتر النقدية (Cash Register):** الخزنة — وارد/مصروف — منفصل تماماً عن دفتر الديون
- **الشغلانات (Jobs):** تتبع كل شغلانة من البداية للتسليم بتكاليفها وأرباحها
- **التقارير المالية:** تقارير مفصلة للأشخاص والأرباح/الخسائر والشغلانات

### الهيكل العام:
```
data (localStorage key: warshty_erp_v4)
├── settings           # كلمة السر، التوكن، محاولات الدخول
├── persons[]          # الأشخاص (عملاء، موردين، صنايعية)
│   └── transactions[] # المعاملات الشخصية (أخذت/عطيت)
├── jobs[]             # الشغلانات
│   ├── materials[]    # الخامات المستخدمة
│   ├── laborItems[]   # المصنعيات
│   ├── otherCosts[]   # تكاليف أخرى
│   └── payments[]     # الدفعات المستلمة
├── treasury
│   ├── income[]       # إيرادات الخزنة
│   └── expenses[]     # مصروفات الخزنة
├── ledgerTransactions[] # سجل اليومية (للتوثيق)
└── categories[]       # التصنيفات (مصروف/وارد/مصنعية)
```

## 3. المتطلبات الوظيفية (Functional Requirements)

### 3.1 شاشة البداية والدخول
- شاشة دخول بكلمة سر رئيسية
- أول استخدام: تعيين كلمة سر مع التأكيد
- تذكر تسجيل الدخول (localStorage remember token)
- 5 محاولات فاشلة → قفل لمدة 30 ثانية
- تسجيل خروج نهائي

### 3.2 لوحة التحكم الرئيسية (Dashboard)
- **كارت الخزنة:** الرصيد الحالي + إجمالي الوارد + إجمالي المصروف
- **4 إحصائيات:** عدد الأشخاص، شغلانات نشطة، مكتملة، مستحق التحصيل
- **آخر الشغلانات:** أحدث 3 شغلانات
- **أحدث الأشخاص:** أحدث 3 أشخاص مع رصيد كل شخص

### 3.3 إدارة الأشخاص (Persons CRM)
#### 3.3.1 قاعدة بيانات الأشخاص
| الحقل | النوع | إجباري |
|---|---|---|
| الاسم | نص | نعم |
| رقم الهاتف | نص | نعم |
| التصنيف | اختيار (عميل/مورد/صنايعي/موظف/شركة) | نعم |
| ملاحظات | نص طويل | لا |
| الحالة | نشط / متوقف | تلقائي |

#### 3.3.2 عرض الأشخاص
- قائمة بجميع الأشخاص (كارت: اسم، تصنيف، الرصيد)
- فلترة حسب التصنيف (كل التصنيفات)
- بحث نصي في الاسم والهاتف

#### 3.3.3 تفاصيل الشخص (Person Detail)
صفحة كاملة تحتوي على:
- **Header:** الاسم، التصنيف، الهاتف، أزرار تعديل + تقرير
- **كارت كبير للديون:** الرصيد الشخصي الحالي (أخضر/أحمر)
- **كارت كبير للشغلانات:** إجمالي المستحق من الشغلانات
- **تبويبان:**
  - **الحساب الشخصي:** قائمة المعاملات (أخذت/عطيت) مع الرصيد قبل كل معاملة والتاريخ والملاحظات
  - **الشغلانات:** ملخص المتفق عليه والمدفوع والمتبقي + قائمة الشغلانات
- **Bottom Bar ثابت:** زراير أخذت / عطيت للوصول السريع

#### 3.3.4 المعاملات الشخصية
- نوعان فقط: **أخذت** (green) / **عطيت** (red)
- كل معاملة: تاريخ، مبلغ، بيان (ملاحظات)
- عرض: الرصيد قبل المعاملة + التاريخ + المبلغ + البيان
- الضغط على المعاملة → فتح نافذة تعديل/حذف
- حساب الرصيد: إجمالي الأخذ − إجمالي العطا
- **لا تؤثر معاملات الأشخاص على الخزنة** (دفتر الديون مستقل تماماً)

#### 3.3.5 تقرير الشخص (Person Report)
- **مفصل جداً:**
  - إجمالي الأخذ (عليا كام)
  - إجمالي العطا (دافع كام)
  - الرصيد (صافي الديون)
- فلترة حسب التاريخ (من تاريخ / إلى تاريخ)
- بحث نصي في المعاملات
- عرض كل المعاملات مع التصفية المباشرة

### 3.4 إدارة الشغلانات (Jobs)
#### 3.4.1 إنشاء شغلانة جديدة
| الحقل | النوع | إجباري |
|---|---|---|
| اسم الشغلانة | نص | نعم |
| العميل | اختيار من قائمة الأشخاص | نعم |
| الورشة | اختيار (سيـلا/الفيوم) | نعم |
| نوع المنتج | نص | لا |
| المبلغ المتفق عليه | رقم | نعم |
| المبلغ المدفوع | رقم | لا |
| تاريخ البدء | تاريخ | لا |
| ملاحظات | نص طويل | لا |

#### 3.4.2 عرض الشغلانات
- 3 تبويبات: قيد التصنيع / مكتملة / باقي تحصيل
- فلترة حسب الورشة
- بحث نصي
- كارت لكل شغلانة: الاسم، الورشة، العميل، المبلغ، المتبقي

#### 3.4.3 تفاصيل الشغلانة (Job Detail)
- **Header:** الاسم، الحالة، العميل، الورشة، النوع، تاريخ البدء
- **الملخص المالي:**
  - الخامات (red), المصنعيات (red), تكاليف أخرى (red)
  - إجمالي التكاليف (red, bold)
  - الربح (أخضر/أحمر)
  - المدفوع (أخضر)
  - المتبقي (تحذيري)
- **قسم الخامات:** إضافة متعددة (بدون إغلاق المودال) + حذف
- **قسم المصنعيات:** إضافة + حذف
- **قسم التكاليف الأخرى:** إضافة + حذف
- **قسم الدفعات:** تسجيل دفعة + auto-ledger للخزنة
- جميع التكاليف باللون الأحمر

### 3.5 الخزنة (Treasury)
#### 3.5.1 عرض الخزنة
- **رصيد الخزنة** كبير في أعلى الصفحة
- **تحته مباشرة:** إجمالي الوارد (أخضر) + إجمالي المصروف (أحمر)
- **زرارين (+ وارد / − مصروف)** تحت الإجمالي فوراً
- **قائمة مختلطة:** كل العمليات (وارد + مصروف) مرتبة من الأحدث للأقدم
- تمييز: الوارد بحد أخضر وتصنيف ✅ وارد، المصروف بحد أحمر وتصنيف ❌ مصروف

#### 3.5.2 إضافة وارد
| الحقل | النوع |
|---|---|
| المبلغ | رقم |
| الوصف | نص |
| التصنيف | اختيار |
| التاريخ | تاريخ |
| الورشة | اختيار |

#### 3.5.3 إضافة مصروف
| الحقل | النوع |
|---|---|
| المبلغ | رقم |
| الوصف | نص |
| التصنيف | اختيار |
| التاريخ | تاريخ |
| الورشة | اختيار |
| ربط بشغلانة | اختياري |

### 3.6 التقارير (Reports)
#### 3.6.1 تقرير الأرباح والخسائر (P&L)
- إجمالي الإيرادات (واردات الخزنة)
- إجمالي المصروفات
- صافي الربح/الخسارة
- توزيع حسب التصنيف
- فلترة زمنية

#### 3.6.2 تقرير الأشخاص (مفصل جداً)
- لكل شخص:
  - إجمالي الأخذ (عليا)
  - إجمالي العطا (دافع)
  - الرصيد
  - التصنيف
  - عدد الشغلانات
- فلترة زمنية
- فلترة حسب التصنيف

#### 3.6.3 تقرير الشغلانات
- تفاصيل كل شغلانة: القيمة، التكاليف، الربح والنسبة
- المدفوع والمقبوض

### 3.7 التصنيفات (Categories)
- إدارة تصنيفات المصروفات والواردات والمصنعيات
- إضافة تصنيف جديد

### 3.8 التصميم والواجهة
- **Mobile-First:** أقصى عرض 430px
- **RTL:** عربي بالكامل — مفيش أي كلمة إنجليزي للمستخدم
- **Dark/Light Mode:** افتراضي Dark، تحويل يدوي
- **خط Tajawal:** عربي عصري
- **Bottom Navigation:** 5 أزرار (الرئيسية، الأشخاص، الشغلانات، الخزنة، التقارير)
- **FAB:** زر عائم (+) للإضافة السريعة
- **Bottom Person Bar:** شريط ثابت (أخذت/عطيت) في صفحة تفاصيل الشخص يحل محل الناف بار

### 3.9 أمان البيانات
- تخزين محلي كامل (localStorage)
- كلمة سر SHA-256
- 5 محاولات فاشلة → قفل 30 ثانية
- تأكيد قبل الحذف
- Remember token

## 4. تدفق البيانات (Data Flow)

### 4.1 الفصل بين الدفاتر
```
دفتر الديون (Debt Register) ← منفصل ← الخزنة (Cash Register)
│                                                │
├── persons[i].transactions[]                    ├── treasury.income[]
│   ├── type: 'أخذت'                             ├── treasury.expenses[]
│   └── type: 'عطيت'                             └── مستقل تماماً
└── لا يؤثر على الخزنة

دفتر الشغلانات (Jobs) ← منفصل عن الديون ← مرتبط بالخزنة
│                                                │
├── job.payments[] → auto-ledger                 ├── treasury.income (auto)
│   (يدخل الخزنة أوتوماتيك)                       └── عند تسجيل دفعة
└── لا يؤثر على حساب الشخص
```

### 4.2 حسابات الشخص
- `getPersonBalance` = إجمالي `أخذت` − إجمالي `عطيت`
- موجب (أخضر) = الشخص مديون ليّ (عليا دين)
- سالب (أحمر) = أنا مديون للشخص (عليا دين)

### 4.3 حسابات الشغلانة
- `agreedAmount` − `payments` = باقي التحصيل
- `agreedAmount` − `(materials + labor + otherCosts)` = الربح
- دفعات الشغلانة تروح للخزنة (auto income) + سجل اليومية

## 7. ملاحظات إضافية

- النظام يعمل Offline بالكامل
- لا يوجد Multi-user أو صلاحيات
- لا يوجد سحاب أو مزامنة — كل البيانات محلية
- لا توجد لغة إنجليزية في واجهة المستخدم (حتى أسماء الحقول)
- الفصل التام بين الدفترين (الديون والنقدية) هو أساس التصميم
- الشخص الواحد يبقى ليه حسابين منفصلين: حساب ديون شخصي + حساب شغلانات
