# Business Rules

## أولا: قواعد النظام العام

---

### BR-001 — الحماية بكلمة السر
النظام محمي بكلمة سر رئيسية (Master Password)
- كلمة السر تُخزّن مشفرة (SHA-256) ولا يمكن استرجاعها
- في أول استخدام يتم تعيين كلمة سر — لا يمكن الدخول بدونها
- بعد 5 محاولات فاشلة للدخول، يتم تأخير 30 ثانية قبل المحاولة التالية
- الجلسة تنتهي بإغلاق المتصفح أو تسجيل الخروج اليدوي
- يمكن تذكر الجلسة (Remember Token) للبقاء مسجلاً

---

### BR-002 — النظام يعمل Offline بالكامل
- جميع البيانات مخزنة في `localStorage`
- لا يحتاج إلى اتصال بالإنترنت إطلاقاً
- لا يوجد Server أو Database خارجي
- ملف HTML واحد هو التطبيق بالكامل

---

### BR-003 — لا يوجد حذف دائم للبيانات (Soft Operations)
- لا يوجد حذف نهائي لأي كيان في النظام
- الشغلانات: أرشفة فقط (Soft Archive) — لا حذف
- الأشخاص: يمكن تعطيل الحالة (نشط → متوقف) — لا حذف
- المعاملات المالية (الدفعات، المصروفات، الواردات): حذف مع تسجيل الأثر
- التصنيفات: حذف فقط إذا لم تكن مستخدمة

---

### BR-004 — جميع المبالغ أرقام موجبة (> 0)
- كل العمليات المالية يجب أن تكون رقم موجب فقط (> 0)
- الاتجاه (وارد/مصروف، أخذت/عطيت) يحدد بالنوع وليس بالإشارة
- لا توجد أرقام سالبة في الإدخال إطلاقاً

---

### BR-005 — الفصل التام بين دفتر الديون ودفتر النقدية (الأهم)
```
┌─────────────────────────────────────────────────────────────┐
│                      النظام المالي                          │
│                                                             │
│  ┌─────────────────────────┐  ┌──────────────────────────┐  │
│  │  دفتر الديون            │  │  الخزنة                  │  │
│  │  (Debt Register)        │  │  (Cash Register)         │  │
│  │                         │  │                          │  │
│  │  • معاملات أشخاص        │  │  • واردات الورشة          │  │
│  │  • أخذت / عطيت          │  │  • مصروفات الورشة         │  │
│  │  • مستقل عن الخزنة      │  │  • مستقلة عن الديون      │  │
│  └─────────────────────────┘  └──────────────────────────┘  │
│                                                             │
│  ┌─────────────────────────┐                                │
│  │  الشغلانات              │  ┌──────────────────────────┐  │
│  │  (Jobs)                 │  │  حساب الشخص             │  │
│  │                         │  │                          │  │
│  │  • تكاليف + دفعات       │  │  • الحساب الشخصي         │  │
│  │  • الدفعات ← الخزنة    │  │    (أخذت/عطيت)           │  │
│  │  • مستقلة عن الديون    │  │  • شغلانات الشخص          │  │
│  └─────────────────────────┘  │    (متفَق عليه - مدفوع)  │  │
│                                └──────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

- **معاملات الأشخاص** (أخذت/عطيت) **لا تؤثر على الخزنة** إطلاقاً
- **معاملات الخزنة** (وارد/مصروف) **لا تؤثر على ديون الأشخاص** إطلاقاً
- **دفعات الشغلانة** (payments) تدخل الخزنة تلقائياً كوارد
- **تكاليف الشغلانة** (خامات، مصنعيات، تكاليف أخرى) لا تؤثر على الخزنة — هي تكاليف حسابية فقط
- **الاستثناء الوحيد:** ربط مصروف شغلانة (relatedJobId) — للتوثيق فقط، لا يؤثر على حساب الشغلانة

---

## ثانياً: قواعد الأشخاص (Persons)

---

### BR-100 — أنواع الأشخاص
يوجد 5 أنواع تصنيف للأشخاص:
- **عميل** — من يتعامل مع الورشة لشراء منتج
- **مورد** — من يورد خامات للورشة
- **صنايعي** — نجار، دهان، مركب، عامل
- **موظف** — موظف إداري أو فني
- **شركة** — كيان مؤسسي

---

### BR-101 — بيانات الشخص الأساسية
كل شخص يجب أن يحتوي على:
- **الاسم** (نص — إجباري)
- **رقم الهاتف** (نص — إجباري)
- **التصنيف** (اختيار من التصنيفات الخمسة — إجباري)
- **ملاحظات** (نص طويل — اختياري)
- **الحالة** (نشط / متوقف — تلقائي نشط)

---

### BR-102 — حساب الشخص المزدوج
كل شخص ليه **حسابين منفصلين**:

| الحساب | المصدر | الصيغة |
|---|---|---|
| الحساب الشخصي (الديون) | معاملات أخذت/عطيت | إجمالي الأخذ − إجمالي العطا |
| حساب الشغلانات | الشغلانات المرتبطة به | إجمالي (متفق عليه − مدفوع) لكل الشغلانات |

- الحساب الشخصي منفصل تماماً عن حساب الشغلانات
- لا تؤثر الشغلانات على الحساب الشخصي والعكس

---

### BR-103 — معاملات الأشخاص (أخذت / عطيت)
- نوعان فقط من المعاملات الشخصية: **أخذت** و **عطيت**
- **أخذت (↑ أخضر):** أنا أخذت فلوس من الشخص (الشخص دفع ليّ) = الشخص مديون ليّ
- **عطيت (↓ أحمر):** أنا عطيت فلوس للشخص (أنا دفعت للشخص) = أنا مديون للشخص
- كل معاملة تحتوي على: التاريخ، المبلغ، البيان (ملاحظات)
- يتم حساب الرصيد قبل كل معاملة وتسجيله في واجهة العرض
- الرصيد = إجمالي الأخذ − إجمالي العطا
- **موجب (أخضر):** الشخص مديون ليّ
- **سالب (أحمر):** أنا مديون للشخص

---

### BR-104 — تعديل وحذف المعاملات الشخصية
- أي معاملة شخصية قابلة للتعديل والحذف
- عند تعديل معاملة: يتم إعادة حساب رصيد الشخص بالكامل
- عند حذف معاملة: يتم إعادة حساب رصيد الشخص بالكامل
- لا يتم تخزين الرصيد — يتم حسابه دائماً

---

### BR-105 — لا يمكن حذف شخص مرتبط بشغلانات
- إذا كان للشخص شغلانات (حتى ولو مؤرشفة)، لا يظهر له زر حذف
- يمكن فقط تعطيله (تغيير الحالة إلى "متوقف")
- لو خلصت كل شغلاناته وأرشفتها، يظهر زر الحذف بعد تأكيد

---

### BR-106 — تقرير الشخص
- تقرير لكل شخص يحتوي على:
  - الاسم، التصنيف، الهاتف
  - إجمالي الأخذ (عليا كام)
  - إجمالي العطا (دافع كام)
  - الرصيد (صافي الديون)
  - عدد الشغلانات المرتبطة به
  - إجمالي المتفق عليه والمدفوع والمتبقي من شغلاناته
  - تفاصيل كل معاملة (تاريخ، نوع، مبلغ، بيان)
  - تفاصيل كل شغلانة (اسم، متفق عليه، مدفوع، متبقي)
- فلترة زمنية (من تاريخ / إلى تاريخ)
- فلترة حسب نوع المعاملة

---

## ثالثاً: قواعد الخزنة (Treasury)

---

### BR-200 — معاملات الخزنة
- الخزنة بها نوعان فقط من المعاملات: **وارد** (Income) و **مصروف** (Expense)
- **وارد (✅ أخضر):** فلوس داخلة للخزنة
- **مصروف (❌ أحمر):** فلوس خارجة من الخزنة
- كل معاملة تحتوي على: المبلغ، الوصف، التصنيف، التاريخ، الورشة

---

### BR-201 — رصيد الخزنة
- رصيد الخزنة = إجمالي الوارد − إجمالي المصروف
- الرصيد يُحسَب ولا يُخزَّن (حتى مع إضافة/تعديل/حذف)
- الرصيد يمكن أن يكون موجباً (أخضر) أو سالباً (أحمر)

---

### BR-202 — تصنيفات الخزنة
- كل معاملة في الخزنة يجب أن يكون لها تصنيف
- تصنيفات الوارد الافتراضية: عربون عميل، دفعة من عميل، إيراد بيع، إيراد متنوع، مقبوضات شخصية
- تصنيفات المصروف الافتراضية: كهرباء، مياه، إيجار، رواتب، نقل، صيانة، خامات، إيجار معدات
- يمكن إضافة وتعديل وحذف التصنيفات بحرية

---

### BR-203 — ربط المصروفات بشغلانة (اختياري)
- يمكن ربط أي مصروف بشغلانة معينة (relatedJobId)
- هذا الربط للتوثيق فقط — لا يؤثر على حساب الشغلانة أو الخزنة
- عند حذف الشغلانة (أرشفة)، يبقى المصروف في الخزنة بدون ربط

---

### BR-204 — دفعات الشغلانة ← الخزنة (تلقائي)
- عند تسجيل دفعة في شغلانة:
  - تُضاف تلقائياً كـ **وارد** في الخزنة
  - تُسجل في ledger (دفتر اليومية) للتوثيق
  - تصنيف الدفعة: "دفعة من عميل" (تلقائي)
- عند حذف دفعة من شغلانة:
  - تُحذف تلقائياً من الخزنة
  - يُحذف مدخل ledger المرتبط بها

---

### BR-205 — لا يمكن تعديل معاملة الخزنة المربوطة بشغلانة
- دفعات الشغلانة المضافة تلقائياً إلى الخزنة **غير قابلة للتعديل اليدوي** في شاشة الخزنة
- يمكن حذف الدفعة من شاشة الخزنة فقط (ليس من شغلانة)
- إذا تم حذفها من الخزنة، تنفصل عن الشغلانة

---

## رابعاً: قواعد الشغلانات (Jobs)

---

### BR-300 — تعريف الشغلانة
الشغلانة هي وحدة العمل الأساسية في النظام:
- لها اسم وعميل وورشة ونوع
- لها هيكل تكاليف متكامل
- لها حالة مسار (Active / Completed / Archived)

---

### BR-301 — حالات الشغلانة
كل شغلانة لها حالة واحدة فقط:

| الحالة | الوصف | قابل للتعديل | قابل للحذف |
|---|---|---|---|
| **Active (نشط)** | قيد التصنيع | نعم | لا (أرشفة) |
| **Completed (مكتمل)** | تم التسليم | نعم (تعديل بيانات فقط) | لا (أرشفة) |
| **Archived (مؤرشف)** | تم الأرشفة | لا | لا |

- لا يمكن تعديل أي بيانات في الشغلانة المؤرشفة
- يمكن إلغاء الأرشفة (إرجاعها إلى Active)

---

### BR-302 — هيكل تكاليف الشغلانة
الشغلانة تحتوي على 4 أنواع من البنود المالية:

#### 1. الخامات (Materials)
| الحقل | النوع | القاعدة |
|---|---|---|
| الوصف | نص | إجباري |
| الكمية | رقم > 0 | إجباري |
| سعر الوحدة | رقم > 0 | إجباري |
| الإجمالي | رقم | يُحسَب = الكمية × سعر الوحدة |

#### 2. المصنعيات (Labor)
| الحقل | النوع | القاعدة |
|---|---|---|
| البيان | نص | إجباري |
| التكلفة | رقم > 0 | إجباري |

#### 3. تكاليف أخرى (Other Costs)
| الحقل | النوع | القاعدة |
|---|---|---|
| البيان | نص | إجباري |
| التكلفة | رقم > 0 | إجباري |

#### 4. الدفعات (Payments)
| الحقل | النوع | القاعدة |
|---|---|---|
| المبلغ | رقم > 0 | إجباري |
| التاريخ | تاريخ | إجباري (الافتراضي: النهاردة) |

---

### BR-303 — إضافة الخامات المتعددة
- يمكن إضافة أكثر من خامة في نفس الجلسة (المودال لا يُقفل بعد الإضافة)
- كل خامة تُضاف مباشرة إلى القائمة
- الضغط على زر "تم" يُغلق المودال بعد إضافة كل الخامات المطلوبة
- لا يمكن إضافة خامة فارغة أو بدون كمية

---

### BR-304 — حساب الشغلانة المالي
```
إجمالي الخامات     = Σ (الكمية × سعر الوحدة) لكل الخامات
إجمالي المصنعيات   = Σ تكلفة كل بند مصنعية
إجمالي التكاليف الأخرى = Σ تكلفة كل بند تكاليف أخرى
─────────────────────────────────────────────────
إجمالي التكاليف     = إجمالي الخامات + إجمالي المصنعيات + إجمالي التكاليف الأخرى
الربـح              = المتفق عليه − إجمالي التكاليف
المتبقي            = المتفق عليه − إجمالي الدفعات
```

- الربح والمتبقي يُحسَبان ولا يُخزنان
- إذا كان الربح سالباً: يظهر بالأحمر (خسارة)
- إذا كان الربح موجباً: يظهر بالأخضر (ربح)

---

### BR-305 — لا يمكن أن تتجاوز الدفعات المتفق عليه
- إجمالي الدفعات لا يمكن أن يتجاوز المتفق عليه
- عند محاولة إضافة دفعة تزيد عن المتبقي، يتم رفضها مع رسالة توضيحية

---

### BR-306 — كل شغلانة لها عميل واحد
- الشغلانة مرتبطة بعميل واحد فقط (مختار من قائمة الأشخاص)
- العميل يجب أن يكون موجوداً في قاعدة البيانات (لا يمكن كتابة اسم عميل وهمي)
- يمكن تغيير العميل في التعديل

---

### BR-307 — كل شغلانة لها ورشة واحدة
- الورشة: إما **سيـلا** أو **الفيوم**
- يمكن فلترة الشغلانات حسب الورشة
- الورشة تحدد مكان التصنيع

---

### BR-308 — الأرشفة
- الأرشفة هي بديل الحذف النهائي
- الشغلانة المؤرشفة تختفي من القوائم الرئيسية
- تظهر فقط في فلترة "مؤرشف" أو في صفحة الشخص
- يمكن إلغاء الأرشفة (إرجاع الشغلانة إلى Active)

---

## خامساً: قواعد التقارير

---

### BR-400 — جميع التقارير تُحسَب في الوقت الفعلي
- لا يتم تخزين أي تقرير أو نتيجة تقرير في قاعدة البيانات
- جميع التقارير تُحسَب في نفس لحظة الطلب
- أي تغيير في البيانات ينعكس مباشرة على التقارير

---

### BR-401 — تقرير الأرباح والخسائر (P&L)
- مصدر البيانات: الخزنة فقط (واردات + مصروفات)
- **الإيرادات =** إجمالي واردات الخزنة في الفترة المحددة
- **المصروفات =** إجمالي مصروفات الخزنة في الفترة المحددة
- **صافي الربح = الإيرادات − المصروفات**
- لا يدخل في هذا التقرير: ديون الأشخاص، تكاليف الشغلانات (الخامات والمصنعيات)

---

### BR-402 — تقرير الأشخاص
- لكل شخص:
  - إجمالي الأخذ (أخذت)
  - إجمالي العطا (عطيت)
  - الرصيد = الأخذ − العطا
  - عدد الشغلانات المرتبطة به
  - إجمالي المتفق عليه والمدفوع والمتبقي من الشغلانات
- الإجمالي العام: الأخذ الكلي، العطا الكلي، الرصيد الكلي
- فلترة زمنية (من تاريخ / إلى تاريخ)
- فلترة حسب التصنيف

---

### BR-403 — تقرير الشغلانات
- لكل شغلانة:
  - الاسم، العميل، الورشة، الحالة
  - المتفق عليه
  - إجمالي الخامات، المصنعيات، التكاليف الأخرى
  - إجمالي التكاليف
  - الربح (رقم + نسبة مئوية)
  - إجمالي المدفوع
  - المتبقي
- فلترة حسب الورشة والحالة

---

## سادساً: قواعد التصنيفات

---

### BR-500 — أنواع التصنيفات
ثلاثة أنواع من التصنيفات:
- **تصنيف وارد** (Income categories) — للواردات في الخزنة
- **تصنيف مصروف** (Expense categories) — للمصروفات في الخزنة
- **تصنيف مصنعية** (Labor categories) — للمصنعيات (اختياري — يمكن كتابة بيان حر)

---

### BR-501 — حذف التصنيف
- لا يمكن حذف تصنيف إذا كان مستخدماً في أي معاملة
- عند محاولة الحذف، يظهر إنذار بعدد المعاملات المرتبطة به
- يمكن تعديل التصنيف حتى لو كان مستخدماً (التعديل ينعكس على كل المعاملات المرتبطة)

---

## سابعاً: قواعد واجهة المستخدم

---

### BR-600 — القوائم والنافبار
- **Bottom Navigation** (شريط سفلي): 5 أزرار — الرئيسية، الأشخاص، الشغلانات، الخزنة، التقارير
- في صفحة تفاصيل الشخص: **Bottom Action Bar** يحل محل النافبار — زراير (أخذت / عطيت) — مخفيين النافبار
- عند إظهار Bottom Action Bar، تضاف padding للتعويض عن safe-area-inset-bottom

---

### BR-601 — الفلترة والبحث
- الفلترة بالشكل الجديد: شريط واحد (search bar) يحوي داخله حقل بحث نصي + زر بحث + chips فلترة
- عند النقر على chip: تُفعّل الفلترة ويتغير لون الـ chip
- لازم يكون في Chips في الأشخاص (كل / عميل / مورد / صنايعي / شركة / موظف) وفي الشغلانات (كل الورش / سيلا / الفيوم)

---

### BR-602 — حذف البطاقات
- الضغط لفترة طويلة (long press) على أي بطاقة في قائمة → تظهر زراير الحذف
- تأكيد الحذف: مودال تأكيد قبل الحذف النهائي

---

### BR-603 — Dark/Light Mode
- التطبيق يدعم Dark و Light mode
- Dark mode هو الافتراضي
- يمكن التبديل من شاشة الإعدادات
- التفضيل محفوظ في localStorage

---

### BR-604 — PWA
- التطبيق يدعم التثبيت على الشاشة الرئيسية كـ PWA
- عند التثبيت: يشتغل بدون شريط عنوان المتصفح
- يعرض splash screen مع اسم التطبيق
